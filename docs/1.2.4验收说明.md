# 1.2.4 验收说明

适配基准：Deskrawl 1.0.2a，Steam build 25842017，Windows x64。

## 本趟掉落预览

合入 Jarry-Zhou 的 [PR #2](https://github.com/awesomehy/Deskrawl-Assistant/pull/2)，新增「掉落预览」页签。连接游戏后进入在线关卡，读取游戏已经收到的 `RunPlan`，显示各波次的计划物品、金币和药水充能。物品包含图标、品质、原始物品等级、远古／黑雾标志、总孔数和计划词条。

打开页签时立即读取；仅在此页签显示期间每 2 秒刷新，避免同一次读取尚未结束时重复请求。切换关卡替换整份列表；回城、断线、读取失败和版本不支持时清空旧数据，过期请求不能恢复旧计划。没有物品的场次仍显示金币及药水充能。

这是尚未结算的服务器计划，实际获得以游戏结算为准。宝箱内物品、寻宝、采集等额外收益不提前推测；金币合计只包含波次金币。预览不会领取物品、修改奖励、执行托管动作，也不会写入累计掉落或玩家日志数据库。

独立类型配置 `data/loot-plan-types.json` 随程序内置，预览仅接受已核验的上述游戏构建。未来游戏版本即使其他功能通过普通变化自动适配，此预览仍需要独立核验。未知类型保留标识并显示未确认；复制前后复核地图、场次、数组和字段的一致性，异常时拒绝整份快照。详见 [掉落预览说明](掉落预览说明.md)。

## 冲突处理与既有功能

解决 README、资源白名单、页面导航、样式和使用说明中的冲突，保留全部七个页签：装备筛选规则、背包与仓库、掉落预览、托管模式、刷图推荐、经验收益和日志。新增页面沿用游戏品质配色；远古与普通传说同为橙色，黑雾与神圣分别标识。

1.2.3 的完整托管能力继续在普通启动中开放，仍需连接、保存配置并手动启动；既有规则与整理设置优先，不覆盖用户数据。全部八种原生动作配置、384 条前置校验容量和游戏构建校验保持不变。

神圣／黑雾装备及套装／宏伟符文必须收纳且禁止出售、分解，神圣禁止自动穿戴；整批先筛选锁定再处置，主城奖励未清空时禁止入图。掉落预览与托管共用串行游戏访问通道，不使用未结算计划触发整理操作。

## 整合验证

- 736 项 Python 测试、49 项前端测试通过。覆盖计划复制期间变化、未知版本／字段布局、空物品计划、数量和词条格式、接口只读限制、断线清空，以及既有托管、换装、收纳和物品保护逻辑。
- 前端使用实际合入的页面与脚本验证七个页签切换、托管激活、每 2 秒刷新、并发读取抑制、过期响应丢弃、动态文本转义和品质颜色。
- 单文件 exe 在隔离用户数据目录、中文／空格路径及不含外部 Python 的环境验证普通独立窗体和维护入口。新用户默认分区仍为装备第 1／2／3 页、符文第 4 页、宝石第 5 页；未连接时所有自动操作保持停止。
- 核对 exe 中的 Python 模块及静态资源与发布源码一致，包含独立掉落类型配置和 444 张图标，不包含个人规则、装备／掉落快照或数据库。
- GitHub Release 只附 exe；发行文件由实际更新器公开下载并核验大小、SHA256 和 Windows 版本信息。

本次整合与发布验证未连接或操作正在运行的游戏。当前构建的实机数据来源说明沿用 PR 的独立核验记录，不将隔离测试视为重新完成整套实机验收。
