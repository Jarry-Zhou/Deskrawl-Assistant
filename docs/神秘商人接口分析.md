# 神秘商人：解锁、报价与无窗口购买

基于 Deskrawl 1.0.2a／Steam build 25842017 安装文件的元数据、PE 指令和 Unity 资源分析。没有执行购买或解锁游戏设施。

## 解锁状态

三个主城的 `UnlockableObject` 配置均使用 `MysteriousMerchantArea`：20 级、2000 金币、3 个恶魔头骨（`Skull`）。`OnEnable` 调用 `in.epc(GameObject.name)` 判断是否已解锁，该方法查找 `in.nqk` 的字符串 HashSet。读取这份当前角色的实际集合，可以在战斗中确认解锁状态；不能以等级、当前金币或材料数量代替已付费解锁标记。

工具在界面、配置保存、托管启动、购买规划和提交原生动作前校验解锁状态。未解锁或读取不完整时不允许开启购买；旧配置中已经开启的开关可关闭。工具不调用 `UnlockableObject.iam` 进行解锁，不代玩家支付金币和材料。

## 报价与菜单刷新

主城以外、购买开关关闭时也读取只读价格预览。`MerchantUI.gzl` 的本地定价为 `ItemData.price × max(1, 玩家等级 / 10 取整)`；在线模式若缓存中存在正数报价则优先使用服务器报价。有效在线缓存报价要求部位、角色等级与难度匹配；没有对应在线报价时显示等级公式的确定数值，并注明来源，不加入可执行购买的 `stock`。进入购买流程仍先打开原商人、刷新实际在线报价并核对碎片扣款。

购买保留比例为 0% 时，无需将余额消耗至零。下一件计划商品超出剩余预算，消费流程关闭商人，记录当前余额并继续刷图；不为了消耗零头更换配置的购买顺序。窗口归属与购买后的整理分别记录，刚打开窗口不会触发“购买完成”的关闭分支。

菜单仅在部位名称、图标或资源清单改变时重建。轮询更新价格文本、解锁提示、输入框是否禁用及选中样式，保持图标节点和编辑中的输入框。

## 主城站街直接购买是否可行

**静态代码显示有可行性，尚未实机验证。** `MerchantUI.gzr(ItemData, int)`（RVA `0x5d6850`）没有直接校验面板打开标志；它检查在线请求忙碌、货币、报价与背包空间，再进入原生离线／在线购买分支。

关键依赖是 `MerchantUI.pal`（偏移 192）的支付货币。`gzn`／`gzo` 用该对象读取、扣除货币；为空时转为金币。`MerchantUI.Show` 初始化货币，关闭回调 `ftr` 清理商品 UI 列表但没有清除这一字段。因此“已经正确初始化为灵魂碎片，关闭窗口后继续购买”与“从未打开过正确商人，直接调用购买”存在不同前置条件。

若后续实现无窗口购买，至少仍要确认实际解锁、身处主城、货币身份为 `SoulShard`、本职业与本难度的有效在线报价、背包空格以及请求队列；每次购买核验新物品 UID、部位和精确碎片扣款。不能仅去掉工具的 `open` 检查，也不能用参考价提交购买。当前版本继续使用自动打开原商人的已实现流程。
