# v1.2.2 验收说明

发布日期：2026-10-11。基准为 Deskrawl 1.0.2a，Steam build 25842017。

## 功能范围

- 托管模式：固定 Boss 面板战力自动换装、指定关卡复刷／跨难度推图、空间门槛回城、奖励整理和累计掉落统计。
- 自动换装按当前职业过滤暗金候选，带图标的就地下拉列表支持搜索、指定名称与禁止该部位换装，两个戒指独立控制。普通、优秀、稀有装备可在开荒期参与；指定暗金已穿上后只在同名装备中升级。替换下来的装备返回背包，神圣装备始终排除，不自动转移宝石。
- 非保留装备按品质配置出售、分解或入库，装备页满时按该件装备的品质选择备用处置；仅清理所选装备页中的未锁垃圾。强化／镶嵌装备仍按用户配置处理，不自动返还消耗。
- 奖励按“先批量拾取，统一筛选锁定，再整理，最后开箱”处理；每次拾取后唤醒同一串行执行器，避免逐件等待两秒。开箱奖励重复整个流程，主城奖励未清空不得入图。
- 自动整理按类型选择马车物品，支持宝石、符文及背包装备分别选择仓库页。新用户为装备 1／2／3、符文 4、宝石 5；已有本地数据优先。未解锁页保留选择，只使用实际开放格位；没有目标页时等待／暂停并保留物品，解锁后刷新即可使用。
- 主动停止先回城整理，再停止；暂停／立即停止停止新动作。托管期间可选择启用既有规则监控与自动整理，两者使用同一执行通道。
- 统计区分神圣、黑雾传说、远古传说、普通传说、稀有、优秀、普通及符文、宝石；低品质游戏自动处置使用系统日志，传说以上使用原生马车记录，助手操作使用已确认回执。启动前库存与搬运不计新增；日志被覆盖或读取缺失时提示统计可能不完整，不用估算补齐。

## 不可修改的保护

神圣、黑雾装备及套装／宏伟符文禁止出售和分解，必须收纳；神圣装备禁止自动穿戴。背包整批装备完成筛选锁定前不处置垃圾。主城地面／马车完整读取并确认收完、保护物品收纳完成后才允许入图。规划、执行和原生入口分别核验，读取待核验或目标容量不足时保留物品并暂停。这些约束只控制助手操作，游戏自身的马车自动处置设置属于独立通道。

## 实测与实验入口

用户托管验收期间的已确认回执包括换装 2 次、回城 3 次、入图 2 次、地面拾取 44 次、开箱 18 次和分解 48 次；另外有马车收取 34 次、转移 44 次和锁定 3 次。仅汇总成功回执，不发布个人物品、存档或运行日志。

以上六种新原生动作在精确构建校验通过后正常开放。助手主动出售和难度切换没有实机成功回执，保留显式实验入口：先退出普通实例，用 `Deskrawl-Assistant-v1.2.2.exe --test-managed` 启动。实验入口不伪造已验收状态，不自动运行托管，也不关闭物品保护、构建校验或动作回读。

普通启动可仅使用自动换装。当前难度复刷无需难度切换能力，但装备处置／满仓备用策略须均选分解，符文、宝石选入库；其他难度或推图要求实验入口。新原生动作依赖精确构建指纹，不因读取侧的普通变化自动适配而放宽校验。

## 发布检查

- 708 项 Python 与 40 项前端测试通过，覆盖策略、保护屏障、旧计划复核、异步旅行、难度推进、停止与续跑、统计去重、未解锁页和本地配置保留。
- 原生邮箱在本进程模拟 ABI、64 位 GC 句柄、参数和取消，不执行真实游戏出售／分解。
- 打包后的普通原生窗体和显式测试入口分别在独立数据目录、中文／空格路径、无外部 Python 的环境通过启动、资源读取、重复启动、默认配置与保存后重启检查。验证过程中不连接或改动正在运行的助手／游戏。
- 发布只附单文件 exe，内置图标、词典、网页和必要运行环境；不附个人规则、装备快照、数据库或日志。

战力估算沿用既有面板模型，不完整预测新暗金特效、技能联动或真实 DPS。保护规则与新默认分区的边界场景通过模拟验证，不能宣称所有新边界已在实机触发。

## 发布后补充实机验证（2026-10-11）

使用显式测试模式及与界面相同的托管执行器，在真实游戏中逐项验证，没有启动整套托管清理，也没有修改用户的规则或整理配置。

- 主动出售：选择未锁定、未命中规则、未强化、未镶嵌且无法提升换装战力的 835 级普通传说「黑鸦反曲弓」。只出售一件，确认该物品移除，金币从 12,545,549 增加至 12,546,065，收入 516 金币。
- 难度切换：回城并确认地面与马车均已清空、背包没有必须收纳的特殊物品后，完成炼狱 → 噩梦 → 普通 → 炼狱。三次原生调用及难度回读均成功，每次对应的 76 个关卡难度标记正确，通关数分别为 70／71／71，最终恢复炼狱并留在主城。
- 发现并本地修复满背包校验容量问题：28 件装备加 12 个其他物品的真实切图前置检查需要 276 条记录，原上限 256 导致调用前被拦截。现将校验记录容量设为 384，保留所有检查及 16 KiB 分配上限；新增本进程原生测试确认第 256 条之后的校验失败仍能阻止所有游戏调用。
- 修复后 710 项 Python 测试通过，游戏保持运行。此次仅确认当前运行状态，没有通过退出／重登证明服务器保存；私人快照及回执保存在本地，不随源码发布。

此修复及补充实测用于 [1.2.3 完整托管开放](1.2.3验收说明.md)。GitHub 上已发布的 1.2.2 exe 保持不变，该旧版的主动出售与难度切换仍需 `--test-managed` 入口。
