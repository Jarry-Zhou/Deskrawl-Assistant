# 1.2.5 验收说明

适配基准：Deskrawl 1.0.2a，Steam build 25842017，Windows x64。

## 掉落预览与高价值监控

当前游戏资源中的 573 个精确物品 ID 均有中文名称和本地图标：209 件装备、36 种宝石、199 种符文、129 种其他物品。效果说明沿用游戏文本与序列化属性；资源存在不等于该物品一定可以掉落。未来未知 ID 保留原始标识并明确显示未确认。

符文品质使用实际静态物品数据及游戏配色。装备卡片分为基础属性、主词条、副词条与未确认词条，复用背包分类和已启用的筛选组合，显示命中高亮、符合规则及主词条全中；固定护甲、武器速度和武器伤害不参与随机词条计数。

独立监控开关每 2 秒检查计划和实际新增物品，切换页签后继续工作，重启默认关闭。发现神圣、黑雾装备、宏伟符文或符文套装时，在本机保存该局原始掉落计划和实际观测证据；普通局只缓存最近四局。已有物品与跨容器移动不重复记录，只有 UID／dropId 与物品 ID 同时对应才认定精确匹配。同局重新开启监控恢复最早证据，损坏的留档保留并提示错误。

监控不领取奖励，也不把未结算计划计入累计掉落。没有记录不能证明高价值物品不在计划中，仍需玩家长期运行积累实机证据。使用方式与局限见[掉落预览说明](掉落预览说明.md)。

## 修复与交互

- 合入 [PR #3](https://github.com/awesomehy/Deskrawl-Assistant/pull/3)，排除属性字典中已删除的条目，快照变化保持可重试，修复武僧等角色读取失败导致托管无法启动的问题。
- 合入 [PR #4](https://github.com/awesomehy/Deskrawl-Assistant/pull/4)，预览和换装规划跳过佩戴等级不足的装备，从仓库取出前、实际穿戴前再次检查当前角色等级。未知条件保守跳过，神圣装备仍禁止自动穿戴。
- 托管模式移到第三个页签，掉落预览移到第四个。托管运行时显示绿色“运行中”和呼吸动画，切换页面仍更新，暂停、停止、断连后隐藏；系统减少动态效果的设置关闭动画。
- 源码启动脚本检测到已打包版本的规则目录时复用原有规则、托管和整理设置；显式数据目录覆盖优先。打包版继续使用原有用户数据目录，不覆盖配置。

## 发布验证

- 804 项 Python 与 51 项前端测试通过，覆盖掉落读取、分类与高亮、证据保存和恢复、等级限制，以及既有换装、托管、收纳和物品保护逻辑。
- 使用隔离模拟页面核验分组、品质配色、监控开关、页签顺序，以及运行／暂停／停止／断连时的状态展示。源码窗体已由用户查看，配置目录修正后重新加载原有 46 条筛选规则。
- 单文件 exe 在隔离用户目录、中文和空格路径、没有外部 Python 的环境验证普通独立窗体及显式维护入口，检查保存并重启后的规则和整理设置。启动后不自动连接或开启监控、整理、托管。
- 核对内置 Python 模块及静态资源与发布源码一致，包含全部 573 张图标、精确物品字典、计划类型配置和更新脚本，不包含个人规则、实际掉落留档、物品快照或玩家数据库。
- GitHub Release 只附 exe；校验发行大小、SHA256、Windows 版本信息与更新器的公开下载流程。

本次打包验证不连接或操作正在运行的游戏。隔离测试不替代游戏内实机验收；既有高价值物品保护、先筛选锁定后处置、入图前清空主城奖励等约束继续生效。
