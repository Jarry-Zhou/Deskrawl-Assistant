# 托管模式（v1.2.2）

v1.2.2 包含托管与分区整理。换装、回城入图、地面拾取、开箱和分解已有成功回读记录，在当前精确构建中正常开放；主动出售、切换难度仍通过显式测试入口启用。助手启动后不会自动连接或开始托管。

## 不可修改的保护规则（2026-10-11 盘查）

- 主城地面物品、马车物品及卸货必须全部收取；背包内必须保留的物品完成收纳后，才允许进入地图或切换难度。地面／马车读取不完整或缺少完整性标记时等待，不能按空列表放行。规划完成后重新检查，原生调用前再检查一次；主线程同时校验地面列表、卸货状态、背包空格内容和受保护物品品质，避免新掉落或卸货插入时使用旧计划。
- 神圣、黑雾装备、套装符文和宏伟符文禁止出售或分解。装备先锁定再存入装备所选页；套装和宏伟符文强制存入符文所选页，包括已锁定符文，覆盖普通符文的出售设置。所选页已满或物品读取未确认时暂停，物品留在背包，地面／马车未收取的奖励保留原处。不会借用未勾选页或用出售／分解作为这些物品的溢出策略。
- 神圣装备禁止自动穿戴，无论战力提升、指定暗金名称或是否已有锁标记。背包、仓库候选均排除，执行旧换装计划和原生穿戴入口再次复核。
- 普通符文仍可按配置出售；符文类型或品质无法确认时禁止处置。符文存放页在普通符文设为出售时仍需选择，用于收纳套装／宏伟符文。旧配置没有选页时保留文件并提示补选，不自动改变其他配置。

盘查发现并修复：宏伟／套装符文此前受普通符文出售策略控制，桥接观察丢失符文类型和品质，神圣装备此前允许按战力穿戴，以及入图前没有再次检查新到奖励。保护共用同一策略，由规划、执行复核及原生操作入口共同执行，配置不能关闭。

回归测试使用模拟状态与本进程内的邮箱编码，不操作实际游戏；覆盖旧计划、强制处置请求、满仓、读取不完整、卸货填入空格，以及现有资源中的全部套装／宏伟符文。源码修复需重启助手才能生效，本轮没有替换或操作正在运行的助手／游戏。游戏自身设置的自动处置属于独立通道，这些保护约束助手提交的操作。

## 配置与流程

- 自动换装的暗金选择按已读取角色职业过滤，同时保留该职业可用的通用装备；断开或职业暂不可读时不展示其他职业的装备。点击各部位装备框，就地展开带图标的下拉列表，支持中英文名称搜索，选择后直接收起；点击外部、再次点击装备框或按 Escape 可关闭，方向键可以选项导航。靠近窗口底部时向上展开，列表内部滚动，不遮罩整个页面。已有配置遇到职业切换时保留原选择并标注不可用，不会在后台删除；重新选择或取消限制后需点击保存。两个戒指部位分别配置。
- 每个部位的装备选择列表增加带禁止图标的「不参与自动换装」选项，选中后部位按钮也显示禁止图标。此设置按穿戴部位跳过背包／仓库候选的比较和换装执行复核，两个戒指分别控制；原有暗金限制仍保留。重新选择装备或「不限制名称」可恢复该部位参与，保存后生效。旧配置默认所有部位参与，不改写原文件。

- 自动换装使用现有固定单体 Boss 面板战力估算，普通、优秀、稀有装备无需配置词条保留规则即可参与比较。未指定暗金的部位允许除神圣以外的所有品质；指定暗金但尚未穿上时，允许普通、优秀、稀有装备作为过渡，仍排除其他名称的暗金。穿上指定暗金后，只在同名装备中升级，不再换回过渡装备。两个戒指槽独立判断；只换超过最小提升门槛的装备，每次换装后重新读取整套装备，执行前按当前穿戴状态复核限制。回城先完成保留装备锁定，再换装，最后出售／分解垃圾。不会自动移植宝石，该估算尚未完整模拟新暗金效果和实际 DPS。
- 自动刷图同时选择普通／噩梦／炼狱难度与关卡，旧配置默认沿用启动时当前难度。推进路线来自关卡真实前置关系；普通最后一关通关后从噩梦第一关继续，噩梦末关后进入炼狱首关，炼狱末关继续复刷。失败后回到本次已通过的上一关及其难度复刷，包括跨难度回退；暂停续跑保留路线。背包空位严格小于设置的门槛时回城。
- 切换难度先回到主城并完成奖励整理，再调用游戏原生切换方法，回读难度确认后入图。按各难度实际通关集合分别读取开放地图；普通通关不能代替噩梦／炼狱通关，未解锁难度和缺少入场材料不会绕过。
- 回城后先完整读取和判定奖励，将本轮所有黑雾、神圣或符合任意启用组合的装备锁定并回读确认，再进行收纳或垃圾出售／分解。马车、地面拾取和开箱产生的新物品都必须重新经过这个锁定阶段。
- 装备、符文与宝石分别勾选存放页。只使用实际已开放的页，宝石只在所选页中堆叠；不会借用未勾选页。
- 未命中装备按远古传说、普通传说、稀有、优秀、普通分别设置出售、分解或存入仓库，以及仓库满时的出售／分解策略。装备页满时，清理这些页原有的未命中装备也使用被清理装备自身品质的策略。没有启用筛选规则的装备也按未命中处理；已强化／镶嵌但未命中的装备仍按配置处置。旧版统一处理方式在内存中迁移为五个品质的相同设置，保留原有选择，点击保存后才写入文件。快捷预设「普通／优秀出售，其余分解」只修改草稿，保存后生效。
- 黑雾、神圣、已锁定、符合保留规则及读取待核验的装备不能出售或分解。已锁定装备也移入装备专用页。容量不足且没有可清理物品时暂停；腾出容量后继续，保留本次掉落统计。
- 回城先连续收取马车与地面物品，优先非宝箱奖励；收完或背包满后才统一筛选、锁定、换装与整理。背包满时完整处理当前批次，再腾出空间收下一批，不在每次拾取后切回处置。所有外部奖励与背包装备、符文、宝石处理完后才开宝箱；开箱产生的新奖励重新经过收取与锁定阶段，全部处理完再进入关卡。
- 每次确认拾取后唤醒同一个串行工作通道继续本批次，不再等待默认的 2 秒观察周期。拾取后发布背包快照时暂不重复读角色，下一轮正常观察会刷新角色。拾取接口自身仍按实际物品身份、接收数量及原生容量限制重新核验并确认结果；锁定、换装、出售、分解和开箱保持执行前完整复核。没有动作、状态待确认或读取变化时回到常规周期，暂停／停止不会追加拾取。
- 统计以开始托管时的持有物品作为基线，不计初始库存；搬运、换装和堆叠不当作新掉落。装备按神圣、黑雾传说、远古传说、普通传说、稀有、优秀、普通统计，另列符文、宝石和已出售／分解数量。暂停续跑保留本次统计，停止后可清空。顺序沿用原来的品质层级；普通 `#E8E8E8`、优秀 `#6680FF`、稀有 `#FFFF00`、普通传说 `#FF8000`、黑雾 `#CD9BFF`、神圣 `#FFDB9A` 来自只读核验的 `GraphicsConfig`；按用户要求，远古传说与普通传说统一使用橙色 `#FF8000`。配置表和装备品质标签使用同一调色板。
- 自动换装始终先从背包穿戴新装备，仓库候选装备会先取到背包；替换下来的旧装备通过原生 `Inventory.fcc` 返回背包。随后重新读取整套装备与规则结果，回城整理时按既有保护与品质策略处理旧装备：已锁定、符合规则、黑雾、神圣保留入库，其余按配置出售／分解／入库。

## 操作通道

已有锁定、搬运和马车收取沿用经过验证的通道。新增回城、进入关卡、换装、出售、分解、开箱和地面拾取，通过构建指纹校验的 Unity 主线程邮箱调用原游戏方法，保留原生权限、价格、奖励和同步流程。

查看能力或场景不会安装调度器。构建配置的 `verified_kinds` 只包含已记录成功回执的六个动作：`return_town`、`enter_map`、`equip`、`salvage`、`open_chest`、`collect_ground`。主动出售和难度切换显示“待验证”，不允许普通页面启用。监督验证入口不是网页 API；不能从浏览器请求中传入物品地址、任意函数或跳过验证。

本地使用 `run_assistant.pyw --test-managed` 启动时，可由用户在界面配置并启动托管验收。窗口标题标为“托管测试版”，未验收动作显示“测试可用”，并保留 `native_verified=false`；构建指纹、物品保护和结果回读仍生效。测试开关仅通过本地启动参数传入，规则导入、配置和网页请求不能启用它。默认启动仍禁用未验收动作。

发布 exe 同样支持 `Deskrawl-Assistant-v1.2.2.exe --test-managed`，需先退出普通实例。普通启动下，自动换装可单独使用；沿用当前难度的复刷不需要切换难度能力，但所有装备的处置／满仓备用策略必须使用已验证的分解，符文和宝石入库。选择其他难度或跨难度推图仍要求难度切换能力；选择出售仍要求出售能力，不能通过隐藏配置跳过。

每次执行前重新读取身份、数量、锁状态和规则结论。执行回执以及实际状态变化确认后，才提交下一步。地图切换异步等待，不重复请求；暂停／停止会阻止后续动作，已完成操作仍记入统计。

托管与原持续监控、自动整理共用串行工作通道。托管启动后暂停旧开关；托管期间需先暂停，才能修改规则或执行手动背包操作。托管配置独立保存在 `managed-mode.json`，不会在启动时自动启用。

## 自动整理分区

“背包与仓库”中的自动整理同时更新：

- 马车收取按装备、符文、宝石、宝箱、材料／其他五种类型选择，提供全选和全不选，不再逐件配置。
- 宝石、符文、背包快满时的装备入库分别选择仓库页。只在已开放且被勾选的页中寻找目标，宝石的合并堆叠也受此限制。分区满时等待，不借用其他页，也不自动出售或分解。
- 新用户的自动整理和托管分区默认一致：装备第 1／2／3 页、符文第 4 页、宝石第 5 页。已保存的本地配置优先，更新默认方案不会覆盖用户的选择。
- 未解锁的所选页保留勾选并标注“未解锁”，未连接或尚未完整读取时标注“待读取”。运行时按游戏实际开放格位过滤，包括只开放部分格位或不连续的仓库页；解锁后的页在下次读取时自动可用，无需重设分区。
- 某类物品的所选页全部未解锁时，自动整理等待，物品留在背包；托管回城整理暂停并提示解锁或修改分区。未解锁不能视为“仓库已满”触发装备出售／分解的备用策略，也不借用其他物品分区。部分所选页已解锁时正常使用这些页；已解锁但满的装备页仍按原配置处理，强制保护物品继续保留。
- 旧版按名称选择的物品在内存中转换为对应类型，默认存放页为第 1 页，新增符文入库默认关闭。原配置文件只有用户点击保存后才更新；启动仍默认暂停。

静态代码核对确认当前构建的回城清场方法清理敌人和技能实体，没有在该方法中销毁 LootDrop；回城还调用马车的原生整理协程。地面与马车在实际回城后的可读性、在线提交完成时机仍需实机核对，不能将静态分析视作已成功收取。

## 离线验证

测试覆盖奖励锁定屏障、仓库原有垃圾清理范围、强化和镶嵌装备处置、失败后回退复刷、异步场景切换、暂停续跑、累计掉落去重、所选页满／未开放、旧配置迁移及网页接口权限。

原生邮箱在测试进程内调用模拟函数，核对 Windows x64 参数、栈对齐、返回条件和取消行为，不访问游戏进程。拾取回执同时核对掉落减少与接收端增加；换装回执同时核对新装备穿戴和旧装备仍在容器中。仅掉落消失或原生方法返回不能算操作成功。

验收中修复主城没有活动关卡时 `run=null` 导致的空值异常；入图切换时也等待有效运行记录，不将空记录视为成功。未知读取格式仍暂停。后续未预期错误在本地操作日志中保留异常类型和调用栈，方便定位。

2026-10-11 实机启动托管后，Windows 在 `GameAssembly.dll+0x39CF5B` 记录访问冲突；静态反汇编确认此处位于当前构建的 `il2cpp_gchandle_free`。邮箱原先将 Unity 6 的 64 位 GC 句柄截断为 32 位，释放错误地址。现改为在调用记录独立的 8 字节槽（偏移 56）保存、读取及清空完整句柄，避免与控制标志重叠。模拟运行时现使用实际 64 位地址，并覆盖低 32 位全为零的句柄；原代码可复现释放错误，修复后正常释放。该离线验证不会调用游戏。原生请求日志额外记录动作和方法名；游戏退出后暂停且禁止重发完成状态不明确的指令。实机修复仍需再次验收。

关卡进度现使用独立只读通道，读取难度、实际通关记录、入场材料与运行波次证据，不依赖 DPS 推荐中的 `PlayerAbilityController` 或临时战斗属性。刚进入主城时未加载技能控制器也能选关；通关仍需核对关卡身份、完成标志、波数、敌人数量与该难度的通关集合。读取未完成时页面显示原因并禁用自动刷图启动，后台观察刷新成功后恢复列表。

2026-10-11 回城切换验收：日志中 `return_town` 调用 `TownPortalSystem.frj` 后等待 45 秒超时，游戏仍继续复刷。静态核对该快捷键方法在普通／神话结算窗口显示时静默返回，且再次调用可以取消引导，不适合用返回成功来确认请求。改为读取并校验原生结算可见标志：战斗中调用布尔回城入口 `frk` 保留引导，结算／死亡时调用结算回城按钮使用的 `frl`。两者均要求原生返回 `true`，再等实际主城状态确认后整理物品；不修改游戏的自动复刷偏好。原生区域切换事件会关闭结算窗口。请求与超时日志记录方向、关卡、难度、结算与传送标志，游戏继续复刷不能充当已回城的证明。离线测试通过后仍需实机验收回城和重新入图。

界面使用全部拦截为模拟数据的独立无头浏览器检查，未启动助手服务；已检查类型全选／全不选、分区保存、待验证能力不能启动，以及窄窗口布局。

## 验收安排

开发期间只使用本地模拟物品与原生 ABI 测试，不连接、暂停或操作挂机中的游戏和 1.2.1 助手。用户准备验收后，先逐项验证回城、入图、换装、出售、分解、开箱和地面拾取，再验证整条托管流程；完成后再决定版本号、打包和发布。

### 主动结束、后台整理与马车统计

- 点击「回城整理后停止」保留已提交动作的回执与场景确认，回城后继续筛选、锁定、换装、收纳／处置、开箱、收取马车和地面奖励。卸货中的物品不视为空，连续两次确认奖励清空后结束，不再入图。结束过程中可点「立即停止」中止整理；暂停、断开、退出与异常仍立即停止提交新动作。
- 托管设置增加「背包／仓库命中规则自动锁定」「启用背包／仓库自动整理」，默认推荐开启，旧配置在内存中补齐。自动整理使用背包页面保存的类型、容量门槛和仓库分区，刷图期间每次只规划一个动作，与换装、旅行和回城清理共用串行执行器。回城清理保护不受后台开关影响。
- 只读读取 WaveManager.nry 和 nsa。nsa 仅保存传说及以上装备的原生马车 Pickup／Autosell／Autosalvage 记录；按照统计集合身份、重置代数与记录序号去重，启动前记录不回填。游戏自身复刷可能更换关卡 GUID 而保留累计统计，不能把 GUID 改变当成计数清零。
- WaveManager 的普通、优秀、稀有统计仅有累计收取计数，旧版使用稳定马车策略估算并标为「≈」。现改为独立读取日志面板 `hb.nhs: List<ha>` 中的 `ItemDisposed` 事件，按游戏资源 `UI.AutoSold` / `UI.AutoSalvaged` 的 14 种语言模板核验动作、物品名、品质颜色及出售金币。低品质自动处置有逐件日志后不再叠加策略估算；传说及以上仍用包含远古／黑雾标志的 WaveManager 原生记录。
- 当前已核验构建中，这两个日志模板由地面／马车自动处置产生；助手使用的 MerchantUI.gzy 和 hm.ecc 不发布这些日志，其背包出售／分解仍按自身已确认回执统计，避免跨来源重复计数。物品名仅允许已收录的装备名称；宝石、符文、未知格式与无法核验的颜色不会猜测成装备。
- 日志最多保留 1000 条，包含文本、类别、时间。按运行进程、列表身份和逐条记录身份去重，不以文字内容去重，同名同价的连续出售分别计数；日志游标和读取缓存只保留当前窗口，避免长时间托管无限增长。启动前日志不回填；正常的新处置记录在本轮完整扫描后入账，若仍有初始地面物品待区分，则延后一轮核对来源。暂时读不到日志时保留游标，恢复后补记仍在列表中的事件，不以估算填充。日志锚点被覆盖、列表重建、首次读取延迟或格式未确认时，页面注明统计可能不完整。
- 普通掉落总数继续使用 WaveManager 累计计数和当前可见物品；未出售的掉落没有处置日志，不能用出售数代替掉落总数。出售金币另保留在本次统计的 `game_log.sale_gold`，表示计入本次掉落统计的低品质游戏自动出售收入。
- 新增读取只使用现有游戏统计，未增加事件钩子或内存写入；实机验收前仍通过本地托管测试入口运行。
